# Async Task Manager

Сервис асинхронной обработки задач с поддержкой приоритетов, очередей сообщений и горизонтального масштабирования.

## Описание

Проект реализует REST API для управления задачами и отдельный worker-процесс для их фоновой обработки.

Основные возможности:

* создание задач через REST API;
* асинхронная обработка задач;
* поддержка приоритетов;
* получение информации о задачах;
* отмена задач до начала выполнения;
* хранение состояния задач в PostgreSQL;
* доставка задач через RabbitMQ;
* горизонтальное масштабирование worker-процессов.

## Архитектура

Система состоит из следующих компонентов:

### API Service

Отвечает за:

* создание задач;
* получение информации о задачах;
* отмену задач;
* публикацию сообщений в RabbitMQ.

### PostgreSQL

Хранит:

* информацию о задачах;
* результаты выполнения;
* ошибки выполнения;
* историю статусов.

### RabbitMQ

Используется как брокер сообщений.

Поддерживается очередь с приоритетами:

* LOW
* MEDIUM
* HIGH

### Worker

Отдельный процесс, который:

* получает сообщения из RabbitMQ;
* выполняет обработку задач;
* обновляет статус в базе данных.

## Запуск проекта

### Требования

Установленные:

* Docker
* Docker Compose
* uv (для запуска без Docker, тестов)

### Запуск

docker compose up --build

API - `http://localhost:8000`

Swagger - `http://localhost:8000/docs`

RabbitMQ Management - `http://localhost:15672`

## Запуск без Docker и Тестирование

`uv sync` - создать venv

Далее отдельно поднять PostgreSQL и RabbitMQ любым удобным способом (можно отдельными сервисами из docker-compose.yml)

Конфигурации должны соответствовать .env файлу

`uv run alembic upgrade head` - применить миграции к БД

`uv run uvicorn src.api.app:app --reload` - запустить API вне Docker

`uv run -m src.worker.main` - запустить worker вне Docker

`pytest` - запустить тесты

## Допущения и упрощения

В рамках тестового задания были приняты следующие упрощения:

1. Реализован один тип фоновой задачи с имитацией выполнения.
2. Retry-механизм для неуспешных задач отсутствует.
3. Dead Letter Queue (DLQ) не реализована.
4. Отмена задач доступна только до начала выполнения.
5. Авторизация и аутентификация не реализованы, так как отсутствуют в требованиях.
6. Централизованное логирование отсутствует.
7. Метрики и мониторинг не реализованы.
8. Расписание задач и отложенный запуск не поддерживаются.
9. Решение ориентировано на демонстрацию архитектуры асинхронной обработки задач, а не на полноценную production-ready
   систему.
